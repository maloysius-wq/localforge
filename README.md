# LocalForge

**A lightweight, offline-first desktop workspace for software-building AI.**

LocalForge is an early open-source project exploring coding agents that can run locally on CPU-only computers, including older Windows and Linux machines. The eventual goal is **one compact, shared coding foundation**, specialized with tools and documentation for Python, web, mobile, desktop, and later pixel-art workflows.

## Current status: v0.1.0 desktop shell

The initial application includes:

- A Codex-style three-pane desktop UI with a chat composer, project sidebar, and activity panel.
- Native folder picker for adding local projects. **Only their paths are saved; project files are not read or modified.**
- Multiple conversations per project (and a separate scratchpad), with local persistence.
- Dark and light themes, keyboard shortcuts, and workspace settings.
- Clear engine-offline messaging. Prompts are saved, **not answered**, until an actual model runtime is connected.
- Windows installer and Linux packages generated by GitHub Actions.

**Not implemented yet:** a model download manager, llama.cpp integration, streamed AI responses, repository reading/writing, autonomous tools, build/test execution, or GPU/CPU telemetry. Nothing in v0.1 pretends to run those features.

## Downloading a test build (no CLI needed)

1. Open the repository's **Actions** tab, then **Build LocalForge**.
2. Open a successful run from the `main` branch.
3. Under **Artifacts**, download the Windows NSIS installer or Linux package.
4. Install and launch LocalForge like a normal desktop app.

These are unsigned development builds. Windows SmartScreen may warn about an unrecognized publisher. Never bypass security warnings for software you do not trust. On older Windows systems, the **WebView2** runtime may be required. Build success does not guarantee compatibility with every older CPU or operating-system version.

If no successful build exists yet, there is no verified downloadable installer. Check the Actions logs.

## Developing locally

Requirements: Node.js 22+, Rust stable, Tauri 2 platform prerequisites.

```sh
npm install
npm test
npm run tauri dev
```

To check the UI in a browser (without native folder selection):

```sh
npm run dev
```

To package a desktop application:

```sh
npm run tauri build
```

**Everyday users should not need a terminal.** The commands above are only for contributors and the GitHub CI workflow.

## Architecture

- **Frontend:** React, TypeScript, Vite, system WebView (Tauri 2).
- **Native shell:** minimal Rust/Tauri application, with only the native folder-picker permission enabled.
- **Persistence:** versioned local browser/webview storage. This is suitable for the shell, not a final project database. Storage migration to SQLite is planned before substantial agent output is stored.
- **AI engine (planned):** `llama.cpp` CPU-only inference, with a lightweight coding model such as Qwen2.5-Coder-1.5B.
- **Development tools (planned):** repository indexing, targeted diffs, compiler/test invocation with explicit scoped permissions and rollback.

There is **no telemetry, remote API, bundled cloud connection, automatic code execution, or unrestricted filesystem access** in this initial version.

## Roadmap

1. **v0.1 desktop shell:** UI, chat persistence, native project selection, action log, CI packages.
2. **v0.2 local model:** CPU-only llama.cpp backend bundled or installed through UI, model manager, streaming coding chat, memory/performance indicators, native file-based storage.
3. **v0.3 coding actions:** project inspection, file search, proposed patches/diffs, explicit approval, test output, undo.
4. **v0.4 quality benchmarks:** Python and HTML/CSS/JavaScript task suite, reproducible runs on low-RAM older CPUs.
5. **Later:** interchangeable task adapters, Android/Swift/desktop support and an independent pixel-art pipeline.

## Security principles

- Local-first and offline by default.
- No model execution permissions in v0.1.
- Later coding tools should be confined to explicitly selected workspaces, with approvals for destructive or external actions.
- Maintain rollback checkpoints and report verified results rather than imagined outcomes.
